# N개 탐색 적재 알고리즘 (규칙 정의, 코드, 결과)

컨베이어 위에 보이는 다음 N개 박스를 이용해 매 박스마다 "몇 수 앞"을 시뮬레이션해 보고 결정하는 적재 알고리즘입니다.
**학습을 쓰지 않습니다.** 모든 판단 기준은 사람이 정한 규칙과 점수식이며, 안전 규칙은 기존 5-② Hard Mask를 그대로 씁니다.

## 1. 전체 구조

```text
박스 도착 (지금 박스 + 컨베이어 위 다음 N개가 보임)
 └ 4단계 결정: 놓기 / 버퍼에 두기 / 버퍼 박스 꺼내기
     ├ 선택지가 1개뿐 → 그대로
     └ 2개 이상 → N개 탐색 (2장)
          각 선택지를 복사본에서 실행 → 보이는 N개까지 진행 → 끝 상태 점수(3장)
          가장 좋은 선택지가 Rule 결정보다 margin 이상 좋을 때만 바꿈
 └ 5-① 후보 생성 → 5-② 안전 걸러내기 → 5-③ 자리 선택(DBLF)
 └ 놓을 곳이 없으면: 부분 재적재 → 팔레트 마감 (규칙)
```

## 2. 규칙 목록

### 층 ① 안전 규칙 (항상 지킴, 탐색으로도 못 바꿈) — `pac_candidates` 5-②
| 규칙 | 내용 |
|---|---|
| 지지 | 하중 지지 다각형(LBCP) 안에 무게중심, 안전계수 4 |
| 하중 | 아래 박스가 위 무게를 견딜 것, 무거운 박스를 가벼운 박스 위에 두지 않음 |
| 높이 | 적재 높이 1.35 m 이하 |
| 경계·겹침 | 팔레트 밖으로 나가거나 다른 박스와 겹치지 않음 |
| NG | 빈 팔레트에도 못 놓는 박스는 검사(NG) 구역으로 |

### 층 ② 자리 선택 — `world.dblf_choice`
안전 후보 중 **낮은 곳 → 안쪽(y 작은 쪽) → 왼쪽(x 작은 쪽)** 순서(DBLF)로 하나를 고릅니다. 후보는 빈 공간 모서리(EMS)와 기존 박스 꼭짓점(EP)입니다.

### 층 ③ 흐름 결정 — 기본 Rule (`rules.py`) + N개 탐색 (`lookahead.py`)
Rule(탐색이 비교 기준으로 쓰는 결정):
1. 버퍼에 12번 결정 이상 머문 박스가 들어갈 수 있으면 먼저 꺼냄
2. 지금 박스의 최선 자리 지지율 ≥ 0.95면 놓음 (버퍼 박스가 2 cm 이상 더 낮게 들어가면 그걸 먼저)
3. 아니면: 버퍼 박스 중 가장 낮게 들어가는 것 → 없으면 지금 박스를 버퍼에 → 버퍼가 꽉 차면 그냥 놓음

N개 탐색: 선택지가 2개 이상일 때 각 선택지를 시뮬레이션해서, 끝 상태 점수가 Rule 결정보다 `margin`(0.005) 이상 좋으면 그 선택지로 바꿉니다.

**자리 후보 가지 (`place_candidates: K`)**: "놓기"와 "버퍼 박스 꺼내기" 가지를 안전한 자리 K개로 나눕니다. 1번은 항상 DBLF 자리이고, 나머지는 DBLF 순위대로 보되 이미 고른 자리와 **같은 방향·같은 높이에서 10 cm 이내**면 건너뜁니다(같은 자리를 여러 번 계산하지 않게). 첫 결정에서만 자리를 나누고, 이후 결정은 Rule + DBLF입니다. 탐색이 DBLF가 아닌 자리를 고르면 그 후보(5-② 통과)를 그대로 실행합니다.

### 층 ④ 팔레트 규칙 (탐색 안에서도 그대로 적용)
| 규칙 | 조건 |
|---|---|
| 부분 재적재 | 지금 박스와 버퍼 박스 모두 놓을 곳이 없을 때, 위에 아무것도 없는 박스를 최대 2개 옮겨 자리를 만듦 |
| 마감 | 놓을 곳이 없고 채움률 ≥ 30 %면 버퍼 대신 마감, 재적재로도 안 되면 마감 |

## 3. 탐색 방법과 끝 상태 점수

**탐색 (`mode: pilot`, 기본)**: 첫 결정만 모든 선택지를 해 보고, 그다음은 Rule로 보이는 N개를 끝까지 처리합니다. `mode: beam`이면 매 결정마다 갈라져 좋은 상태 `beam`개를 남깁니다.
복사본에는 **보이는 N개까지만** 들어 있어 그 뒤 박스는 읽을 수 없습니다(테스트로 확인).

**끝 상태 점수** (단위: 팔레트 부피 비율, 낮을수록 좋음)

```text
점수 = Σ(이 구간에서 마감한 팔레트의 빈 비율 1 - 채움률)
     + 1.0 × (열린 팔레트 윗면 아래 갇힌 빈 공간 / 팔레트 부피)
     + 0.3 × (열린 팔레트 높이 표준편차 / 팔레트 높이)
     + 1.0 × (앞으로 올 박스 중 이 팔레트에 놓을 곳이 없는 부피 비율) × (1 - 채움률)
     + 0.01 × 버퍼에 남은 박스 수 + 0.5 × NG 박스 수 + 0.0005 × 로봇 시간(초)
```

- 첫 줄: 최종 목표(사용 팔레트 수)는 "박스 총부피 + 낭비된 부피"이므로, 마감한 팔레트의 빈 공간이 그대로 손실입니다.
- 둘째·셋째 줄: 열린 팔레트가 앞으로 낭비할 공간 추정입니다.
- 넷째 줄 ("막힌 팔레트"): 버퍼 박스, 보이는 박스, 주문 목록(순서 없이 남은 종류·개수, 부피 큰 6종)을 각각 5-①·5-②로 검사합니다. 놓을 곳이 없는 비율이 크면 이 팔레트는 곧 마감될 것이므로 그만큼 손실로 봅니다. 이 항이 없을 때는 일부 시나리오에서 팔레트가 채움률 20 %에서 막혀 크게 나빠졌습니다.

## 4. 계산 시간 줄이는 방법

| 방법 | 효과 |
|---|---|
| 가벼운 복사: 바뀌는 목록만 복사하고 후보 생성기·SKU 정보는 공유 | 상태 복사 0.7 s → 수 ms |
| 캐시 공유: 같은 팔레트 상태·같은 크기 박스의 5-①·5-② 결과 재사용 | 버퍼에 두기 같은 갈래는 거의 공짜 |
| 파일럿 방식: 첫 결정만 펼침 | 갈래 수 = 선택지 수(3~5개) |
| 빔 + 같은 상태 합치기 (`mode: beam`) | 더 넓게 볼 때 갈래 제한 |
| 시간 제한 `time_budget_s` | 넘으면 진행 중인 갈래를 그 상태로 평가, 아무것도 없으면 Rule 결정 |
| 자리 가지 순서: 기본(DBLF) 가지를 모두 먼저, 추가 자리는 시간이 남을 때만 | 시간 제한이 걸려도 최소한 자리 없는 탐색 결과는 확보 |
| 비슷한 자리 합치기 (10 cm, 같은 방향·높이) | 자리 가지 수를 실제로 다른 자리로만 제한 |
| "놓을 곳이 있나" 검사를 첫 성공에서 중단 (`has_safe_spot`) | 막힌 팔레트 점수 계산 단축 (후보 전체 검사 대신 낮은 후보부터 하나만 찾으면 끝) |
| (현장) 로봇이 움직이는 7~8 s 동안 다음 결정을 미리 계산 | 런타임 구조, 이번 코드에는 미포함 |

## 5. 결과

데이터: 재성 님 생성기, 240개 시나리오(80박스, 시드 20261008), 168/36/36 분할. 같은 박스 흐름으로 Rule과 짝지어 비교.
설정은 검증(val)으로 고르고, test는 마지막에 한 번만 확인합니다.

### 검증 36개 (`reports/lookahead_val.json`, 시간 제한 없음)
| | 팔레트 | Rule 대비 | 개선/같음/악화 | 로봇 시간 | 결정 시간 평균 / 95 % 최대 |
|---|---|---|---|---|---|
| Rule | 4.16 | | | 1147 s | |
| N = 3 | 3.70 | **−0.46** [−0.62, −0.31] | 30 / 1 / 5 | 1115 s | 0.50 s / 2.9 s |
| N = 5 | 3.67 | **−0.49** [−0.63, −0.35] | 32 / 2 / 2 | 1098 s | 0.70 s / 6.4 s |
| N = 3, 막힌 팔레트 가중치 0.5 | 3.73 | −0.43 | 28 / 1 / 7 | 1121 s | 0.53 s / 4.4 s |

안전 이슈 0, NG 0 (모든 설정).

### test 108개 (`reports/lookahead_test.json`, 결정당 2초 제한, 설정 선택에 쓰지 않은 시나리오)
| | 팔레트 | Rule 대비 | 개선/같음/악화 | 로봇 시간 | 결정 시간 평균 / 95 % 최대 / 최대 |
|---|---|---|---|---|---|
| Rule | 3.83 | | | 1117 s | |
| N = 3 | 3.35 | **−0.48** [−0.57, −0.38] | 89 / 6 / 13 | 1096 s | 0.53 s / 2.8 s / 8.7 s |
| N = 5 | 3.32 | **−0.51** [−0.61, −0.41] | 95 / 4 / 9 | 1091 s | 0.72 s / 5.1 s / 8.9 s |

부호 검정 p < 0.001, 안전 이슈 0, NG 0. 채움률 23.4 % → 26.2 %.
이 평가 때는 시간 제한을 넘겨도 아직 시작하지 않은 가지의 첫 수와 점수 계산을 끝까지 해서 최대 8.9 s가 나왔습니다. 그 뒤 "Rule 가지를 먼저 계산하고, 제한을 넘으면 남은 가지는 건너뜀"으로 고쳤습니다(아래 자리 후보 평가부터 적용).

## 6. 한계
- 결정 시간은 이 클라우드 4코어에서 평가 4개를 동시에 돌리며 잰 값입니다. 2초 제한을 걸면 느린 결정은 일부 갈래만 보고 정합니다.
- 컨베이어 카메라가 박스 크기·무게를 정확히 잰다고 가정했습니다(가상 데이터의 측정 잡음은 포함).
- 5-③ 자리 선택은 DBLF 그대로입니다. 자리까지 탐색에 넣으면 더 좋아질 수 있지만 갈래가 크게 늘어납니다.
- 실제 셀 연동(런타임 노드에서 컨베이어 박스 목록을 `world.arrivals`로 넘기기)은 아직 하지 않았습니다.
