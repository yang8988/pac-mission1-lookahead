# N개 탐색 + 평평한 층 적재 알고리즘 (태현, 최종)

컨베이어 카메라에 보이는 다음 N개(기본 5개) 박스로 매 박스마다 몇 수 앞을 시뮬레이션해 4단계 결정을 고르고, 5-③ 자리는 "평평한 층" 점수로 고르는 적재 알고리즘입니다.
**학습을 쓰지 않습니다.** 모든 판단은 규칙과 점수식이며, 안전 검사는 기존 5-② Hard Mask를 그대로 씁니다.

## 1. 흐름

```text
박스 도착 (지금 박스 + 컨베이어 위 다음 N개 보임)
 └ 4단계 결정: 놓기 / 버퍼에 두기 / 버퍼 박스 꺼내기
     ├ 선택지 1개 → 그대로
     └ 2개 이상 → N개 탐색: 선택지마다 복사본에서 실행 → 보이는 N개까지 Rule로 진행 → 끝 상태 점수
                   가장 좋은 선택지가 Rule 결정보다 0.005 이상 좋을 때만 바꿈
 └ 5-① 후보 생성 (방향 = SKU별 허용 방향) → 5-② 안전 검사 → 5-③ 평평한 층 점수로 자리 선택
 └ 놓을 곳이 없으면: 부분 재적재 → 팔레트 마감 (막힌 팔레트 규칙)
실시간: 로봇이 지금 박스를 옮기는 동안 다음 결정을 미리 계산 (realtime.py)
```

## 2. 규칙

### 안전 (5-②, 탐색으로도 못 바꿈)
| 규칙 | 내용 |
|---|---|
| 지지 | 바닥 지지율 ≥ 70 %, 무게중심이 하중 지지 다각형(LBCP) 안, 팔레트 전체 무게중심 검사 |
| 찌그러짐 | 아래 박스의 허용 하중(골판지 McKee 식 ÷ 안전계수 4, 포장 종류별) ≥ 위에 얹힌 무게 |
| 무거운 박스 금지 | **끔** (미션 항목 철회). 찌그러짐·무너짐 검사로 대신함 |
| 경계·겹침 | 팔레트 밖·겹침 금지, 옆 간격 4 mm |
| 높이 | 데크 위 적재 높이 한계(환경 파일) |

포장 종류(`environment.yaml` → `catalog.packaging`): `corrugated`(McKee), `rigid_crate`(정격 하중), `no_stack`(위에 못 올림).

### 5-③ 자리 선택: 평평한 층 (`placement.py`, `LayerPlacer`)
안전 후보 중 점수가 가장 낮은 자리 (단위 없는 값):

```text
1.0  × 윗면 높이 / 팔레트 높이
+ 0.3  × 주변 비평탄 비율   (윗면 둘레에서 높이가 3 mm 넘게 다른 칸의 비율, 박스 크기와 무관)
+ 0.1  × 단차 크기 / SKU 높이 중앙값
+ 0.05 × (1 - 옆면 밀착 비율)
+ 0.1  × (1 - 바닥 지지율)
+ 0.01 × 모서리 거리
```

단차는 크기와 상관없이 조금이라도 있으면 그 위 박스가 기울어지므로 "있다/없다" 비율로 세고, 크기는 작은 보조 항으로만 씁니다. 허용 오차 3 mm는 5-② 높이 허용값과 같습니다.

### 4단계 기본 Rule (`rules.py`, 탐색의 비교 기준)
1. 버퍼에 `슬롯 수 × 3`번 결정 이상 머문 박스가 들어갈 수 있으면 먼저 꺼냄
2. 지금 박스의 최선 자리 지지율 ≥ 0.95면 놓음. 단, 버퍼 박스가 `지금 박스 높이 × 15 %` 이상 더 낮게 들어가면 그걸 먼저
3. 아니면 버퍼 박스 중 가장 낮게 들어가는 것 → 없으면 지금 박스를 버퍼에 → 버퍼가 꽉 차면 그냥 놓음

### 팔레트 마감: 막힌 팔레트 규칙 (`CloseConfig.mode: dead`)
놓을 곳이 없을 때, **앞으로 올 박스 중 이 팔레트에 놓을 곳이 있는 박스가 하나도 없으면** 마감하고, 하나라도 있으면 버퍼에 두고 기다립니다.
"앞으로 올 박스" = 지금 박스 + 버퍼 + 컨베이어에 보이는 5개 + 주문 목록에 남은 부피 큰 6종(보이는 박스만큼 빼고 셈, 종류별 1번 검사).
기존 규칙(채움률 30 % 이상이면 마감)을 대체합니다.

## 3. N개 탐색 (`lookahead.py`)

- 파일럿 방식: 첫 결정만 모든 선택지를 해 보고, 그다음은 Rule로 보이는 N개를 끝까지 처리합니다.
- 복사본에는 보이는 N개까지만 들어 있어 그 뒤 박스는 볼 수 없습니다(테스트로 확인).
- Rule 갈래를 먼저 계산하고, 시간 제한(로봇 1회 동작 시간 × 0.25 = 2 s)을 넘으면 진행 중인 갈래를 그 상태로 평가합니다.

끝 상태 점수 (팔레트 부피 비율, 낮을수록 좋음):

```text
Σ(구간 안에서 마감한 팔레트의 1 - 채움률)
+ 1.0 × 열린 팔레트 윗면 아래 갇힌 빈 공간 비율
+ 0.3 × 높이 표준편차 / 팔레트 높이
+ 1.0 × 앞으로 올 박스 중 놓을 곳 없는 부피 비율 × (1 - 채움률)
+ 0.01 × 버퍼 박스 수 + 0.5 × NG 수 + 0.0005 × 로봇 시간(초)
```

시간 줄이기: 가벼운 복사(바뀌는 목록만), 5-①·5-② 결과 캐시 공유, 첫 결정만 펼침, "놓을 곳이 있나"는 첫 성공에서 중단, 시간 제한, 로봇 동작 중 미리 계산.

## 4. 환경 파일 (`config/environment.yaml`)

현장이 바뀌면 이 파일만 바꿉니다: 팔레트 크기, 적재 높이, 최대 하중, 버퍼 슬롯 수, 카메라에 보이는 박스 수 N, 컨베이어 간격, 로봇 동작 시간, 결정 시간 비율, 방향 규칙, 포장 종류. 다른 설정 파일에는 알고리즘 값만 남습니다(`apply_environment`).

## 5. 결과 (test 108개, 설정 선택에 쓰지 않은 시나리오)

조건: 팀 생성기 1.4.0 데이터(시나리오당 80박스, 13 SKU, 6 계열, 팔레트 1.1×1.1 / 1.2×1.0 / 1.2×0.8 m, 데크 위 1.5 m), 버퍼 4칸, 보이는 박스 5개, 같은 박스 흐름으로 짝 비교(seed 4242, 시나리오당 3회).
채움률은 **마감된 팔레트 평균**(마지막 팔레트 제외). 팔레트 수는 마지막 팔레트를 채운 만큼만 세는 "팔레트 환산값".

| 알고리즘 | 마감 팔레트 채움률 | 팔레트 수(환산) | 로봇 시간 | 안전 문제 / NG |
|---|---|---|---|---|
| 기존: Rule + DBLF + 채움률 30 % 마감 | 33.9 % | 2.68 | 1036 s | 0 / 0 |
| Rule + DBLF + 막힌 팔레트 마감 | 37.4 % | 2.45 | 1057 s | 0 / 0 |
| Rule + 평평한 층 + 막힌 팔레트 마감 | 39.0 % | 2.38 | 1023 s | 0 / 0 |
| **N=5 탐색 + 평평한 층 + 막힌 팔레트 마감 (최종)** | **42.8 %** | **2.15** | **992 s** | 0 / 0 |

- 최종 vs 기존: 팔레트 −0.53개(95 % CI −0.61 ~ −0.44), 108개 중 99개 좋아짐 / 6개 나빠짐.
- 최종 vs Rule + DBLF(새 마감 규칙): −0.30개(CI −0.38 ~ −0.22), 81 / 17, 부호 검정 p < 0.001.
- 탐색: 결정당 평균 0.79 s, 탐색이 Rule 결정을 바꾼 비율 15.9 %.

원본: `reports/test_v2_final.json`, `reports/test_v2_oldrules.json`.

## 6. 실행

```bash
python3 tools/highlevel/scripts/make_dataset.py                       # 데이터 생성 (팀 생성기)
python3 tools/highlevel/scripts/evaluate_lookahead.py --dataset tools/highlevel/output/dataset80_x40_s8 \
    --split test --passes 3 --variant N5L=policy=lookahead --output reports/my_eval.json
python3 tools/highlevel/scripts/run_realtime.py --dataset tools/highlevel/output/dataset80_x40_s8 \
    --split test --episode 0 --output reports/realtime_test0.json   # 실시간 타임라인
python3 -m pytest -q tests/taehyeon/test_th_lookahead.py tests/taehyeon/test_th_realtime_demo.py
```

시연(3D 뷰어, Live 시뮬레이터, Gazebo)은 `docs/realtime_demo.md`.

## 7. 한계

- 마감 판단은 주문 목록 중 부피 큰 6종만 보고, 버퍼 선반의 크기(놓을 수 있는 바닥 넓이)는 모델링하지 않았습니다.
- 5-③ 자리는 탐색이 고르지 않고 평평한 층 점수가 고릅니다(탐색은 행동만 고름).
- 6단계 로봇 도달·충돌 검사는 탐색에 들어 있지 않습니다. Gazebo 셀 기준 표본 80박스 중 17개가 6단계에서 거부됩니다.
- 결정 시간은 클라우드 4코어에서 평가 7개를 동시에 돌리며 잰 값입니다. 2 s 제한을 넘긴 결정(최대 9.1 s)은 Rule 갈래 계산이 길었던 경우입니다.
- 박스를 세워 놓는 방향(옆으로 눕히기)은 아직 없습니다.
